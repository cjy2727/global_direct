# 제품 범위

현재 구현은 상품 URL을 받아 상품 정보와 옵션, 상세 정보, 분석 상태를 JSON으로 반환합니다.
결과 표시 및 이후 구매대행 업무는 호출 측에서 담당합니다.
포함: 공개 상품 페이지 분석, 옵션/조합 수집, 분석 상태, CORS.
제외: 화면, 로그인, 상품 DB 저장, 장바구니, 주문, 결제, 배송. 분석 작업과 캐시는 단일 워커 메모리에서 관리하며 AI 일일 사용량만 파일로 보존한다.
원본 사이트에 따라 결과가 달라지며 needs_review 상태를 해석해야 합니다.
API 계약은 README.md를 참고하세요.

## 범용 상품 수집 정책

목표는 상점별 사전 구현 의존도를 낮추고, 가능한 많은 공개 상품 페이지에서 이미지·상품명·가격·할인정보·옵션·상품상세를 수집하는 것이다. 모든 상점의 완전한 수집을 전제로 하지 않는다.

- 허용된 운영 Global Shopping API를 우선 사용한다. 해당 경로를 사용할 수 없는 상점은 Playwright로 구조화 데이터·DOM·관련 네트워크 응답을 분석한다. 개발 호스트는 운영 API 판별 대상에 추가하지 않는다.
- 범용 수집으로 부족한 정보는 AI 분석과 제한된 옵션 탐색으로 보완하는 것을 목표로 한다. 상점별 전용 처리는 필요한 경우에 추가한다.
- 일부 필드나 옵션을 수집하지 못했다는 이유만으로 확보한 상품 정보까지 폐기하지 않는다. 확인하지 못한 값은 추측하지 않고 누락 또는 미확인 상태와 사유를 반환한다.
- 판매가·원가·쿠폰가·회원가·옵션 추가금을 구분하고 확인된 적용 조건을 보존한다. 미확인 옵션 추가금이 있으면 기본 상품가를 최종 확정가로 취급하지 않는다.
- 옵션 수집 실패 시 텍스트 입력 항목으로 대체한다. 상세 규칙은 [상품 옵션 수집 정책](OPTION_EXTRACTION.md#옵션-직접-입력-대체-정책)을 따른다.
- 이 프로젝트는 입력 항목 정의와 분석 상태를 JSON으로 반환하며, 실제 입력 화면은 호출 측에서 표시한다.
- 장바구니 추가·주문·결제는 실행하지 않는다.

처리 순서는 (1) 허용된 운영 Global Shopping 위젯·API 확인 후 상품 API 사용, (2) 내부 API를 사용할 수 없으면 기존 Playwright 분석, (3) 정보가 부족하면 AI가 Chromium 도구로 페이지를 추가 탐색하는 순서다. AI는 페이지 읽기·스크롤·상세/옵션 펼치기·선택·대기를 결정하고, 실행 후 바뀐 DOM을 다시 확인한다. 별도의 브라우저를 열어 이전 수집 결과를 버리지 않고 현재 상품의 격리된 Chromium 페이지를 이어서 탐색한다. 스크린샷/이미지 내용 해석은 포함하지 않는다. 확인된 결과를 보존하고 관찰된 요소 ID로 옵션·상세를 보완하되 전체 조합·재고의 완전성은 보장하지 않는다.

## AI 사용 설정 정책

환경변수 `AI_ENABLED`로 사용 여부를 제어한다. 기본값은 `false`이며, 설정이 없으면 AI를 사용하지 않는다.

- `true`: 기존 API·Playwright·DOM 수집 후 부족한 정보를 AI의 Chromium 탐색으로 보완한다.
- `false`: AI 호출과 AI 기반 탐색을 모두 건너뛴다. 기존 API·Playwright·DOM 수집 및 AI에 의존하지 않는 옵션 탐색은 계속 수행한다.
- 옵션 직접 입력 대체는 AI 사용 여부와 독립적으로 적용한다. AI를 사용하지 않더라도 옵션 수집 실패 시 텍스트 입력 항목을 제공한다.
- 분석 결과에는 설정에 따른 AI 미사용과 AI 분석 실패를 구분하여 표시한다. AI 미사용 자체를 분석 실패로 처리하지 않으며, 수집 정보의 완전성에 따라 상품 상태를 판단한다.

제공업체·모델·접속 주소·키는 `AI_PROVIDER`, `AI_MODEL`, `AI_BASE_URL`, `AI_API_KEY`로 설정한다. 현재 제공업체 연결은 `openai`만 구현되어 있으며 다른 값은 `unsupported_provider`로 건너뛴다. Claude 등은 연결 모듈 추가가 필요하다. 키는 서버에만 보관한다. 연결 실패·설정 누락·한도 초과는 `aiAnalysis`로 구분하고 기존 수집 결과를 보존한다. 설정과 API 계약은 [README](../README.md#ai와-공개-서비스-설정)를 참고한다.

## 공개 서비스 운영 제한 설정 정책

홈페이지에서 불특정 다수의 사용자가 상품 분석을 요청하는 운영을 위해 아래 설정을 서버 환경변수로 관리한다. 실행 코드에 연결되어 있으며 설정 화면은 제공하지 않는다. 대기열·캐시·요청 제한은 단일 Node 프로세스에서 관리한다.

| 설정 | 제어 내용 |
| --- | --- |
| `AI_ENABLED` | AI 사용 여부. 기본값 `false` |
| `ANALYSIS_CONCURRENCY` | 동시에 실행할 상품 분석 수 |
| `ANALYSIS_TIMEOUT_SECONDS` | 상품 분석 최대 실행 시간 |
| `QUEUE_MAX_LENGTH` | 실행을 기다리는 최대 작업 수 |
| `QUEUE_WAIT_TIMEOUT_SECONDS` | 작업의 최대 대기 시간 |
| `RATE_LIMIT_ENABLED` | 사용자·IP별 요청 제한 사용 여부 |
| `RATE_LIMIT_PER_IP_PER_MINUTE` | IP별 분당 요청 수 |
| `RATE_LIMIT_PER_USER_PER_MINUTE` | 신뢰할 수 있게 식별 가능한 사용자별 분당 요청 수 |
| `CACHE_ENABLED` | 상품 분석 캐시 사용 여부 |
| `CACHE_TTL_SECONDS` | 캐시 유효기간 |
| `AI_CONCURRENCY` | 동시에 실행할 AI 호출 수 |
| `AI_TIMEOUT_SECONDS` | AI 호출 최대 시간 |
| `AI_BROWSER_MAX_STEPS` | AI 브라우저 분석의 최대 모델 요청 수(최종 결과 요청 포함) |
| `AI_BROWSER_TIMEOUT_SECONDS` | AI 브라우저 분석 전체 시간 제한 |
| `AI_DAILY_REQUEST_LIMIT` | 일일 AI 호출 한도 |
| `AI_DAILY_BUDGET` | 일일 AI 비용 한도 |

- 같은 상품의 진행 중 요청은 하나의 분석 작업으로 합친다. 캐시를 사용하면 유효기간 내 결과를 재사용하고, 가격·재고의 확인 시각을 제공한다.
- 대기열이 가득 차거나 최대 대기 시간을 초과하면 상태와 재시도 안내를 반환한다. 요청 제한에 도달한 경우에도 제한 사유를 구분한다.
- AI 호출·비용 한도에 도달하면 AI 단계만 건너뛰고 확보한 상품 정보와 필요한 옵션 입력 항목을 반환한다. 설정에 따른 미사용, 한도 초과, AI 실패는 구분한다.
- 비용은 제공업체의 사용량 정보와 모델별 요금에 근거해 계산한다. 진행 중 호출과 사용량 집계 지연으로 애플리케이션의 한도만으로 정확한 청구 상한을 보장하지 않으며, 제공업체가 지원하는 예산·사용량 제한도 함께 설정한다.
- 인증되지 않은 요청에 임의의 사용자 식별값을 신뢰하지 않는다. 사용자 식별이 없으면 IP별 제한을 적용하며, 프록시 환경의 실제 IP 판별은 신뢰할 수 있는 프록시 설정을 기준으로 한다.
- AI 키와 운영 제한 설정은 서버에서 관리한다. 일반 사용자의 분석 요청으로 변경할 수 없도록 한다.

기본값과 적용 방법은 [README](../README.md#ai와-공개-서비스-설정)와 `.env.example`에 정의한다. 유효 범위를 벗어난 설정은 워커 시작을 실패시킨다. 비용은 USD, 일일 한도는 UTC 00:00 기준이다. 환경변수 변경은 컨테이너 재생성이 필요하다. 동시 실행 수는 실제 부하 측정에 따라 조정하며 AI 기능과 별개로 브라우저 자원을 제한한다.
